# Native navigation timing source audit

Source generation only. No build, binding generator, test, WPT or service execution has occurred for this batch. The parent navigation timing and prerender gates remain open.

## Generated production routes

- `oryn-js/navigation_timing.rs` holds a shared native navigation record, original monotonic start and epoch mapping, response/redirect provenance, once-only lifecycle stages, strict-origin unload masking and activation time. Clones preserve the clock across retained callbacks, BFCache and prerender activation.
- `resource_timing.rs` exposes a live `PerformanceNavigationTiming` through the native timeline, JSON and observer routes. Resource-buffer clearing preserves navigation entries. Worker supported-entry lists exclude navigation.
- Root HTTP navigation creates its record at transaction admission, carries it through header/MIME preparation and response/body custody, and installs it before Document author execution. Buffered/local actor navigation carries the same transaction record. Standalone snapshot fallback captures construction entry time.
- Parser-created and dynamic frame loads retain native timing through prepared response ownership. Initial Window reuse and replacement install the record before script bootstrap. Stream EOF updates the same record; charset replay does not manufacture another response or release its timing custody.
- Native DCL/load delivery records start before callbacks and end only after retained delivery completes for the original stream. Readiness transitions record interactive/complete stages. Prerender activation records activationStart before changing the Document's prerendering flag.
- Optional `ResourceTimingMetadata.producer_clock_micros` aligns authenticated same-host response metadata using the platform monotonic clock. Missing anchors remain unavailable. Wall-clock values are used only for the epoch-form time origin, never elapsed durations.

### Terminal encoded-byte provenance generated

The compressed unknown-length concern above now has production source integration. Native synchronous and asynchronous transports count received body bytes **before decompression**. Only successful body EOF publishes the optional count; failed/canceled bodies do not manufacture completion. `NetworkEvent::Complete` and its encoded broker representation carry the optional value. Full-response collectors retain it in `TransportTiming`; root NavigationBodyChunks consumes it directly. Parent stream reads transfer it on the exact terminal `HttpStreamChunk`, frame decoders consume it after their original body reaches EOF, and the typed platform chunk/resource-timing queue updates the original request record. Service-response reuse retains representation size without old timestamps. Header Content-Length remains an estimate only where raw size was not measured.

Memory/persistent cache records now preserve original encoded representation size. Cache-hit synchronous streams retain cache delivery and size metadata; 304 replay combines original representation size with fresh revalidation phases. Synchronous caching readers now wait for real EOF (including framing validation), rather than storing a representation solely because the advertised length has been read; zero-length caller buffers cannot masquerade as EOF. Their optional count is never published by cancellation/drop. Original response identity and live demand/cancellation ownership are unchanged.

Generated regression sources cover raw gzip measurement independently of decoded bytes and supplied Content-Length, encoded broker roundtrip (unknown/zero/measured), parent exact terminal publication, frame decoder replay with distinct encoded/decoded counts, once-only navigation size capture, and cache publication only after EOF. No execution. Generic resource workerStart and broader dynamic timing-helper inventory remain the explicitly separate source residuals; this terminal-byte group does not claim all Necessary navigation/resource timing conformance.
