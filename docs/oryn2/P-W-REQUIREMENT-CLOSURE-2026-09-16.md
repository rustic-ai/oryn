## September 17 reset HTTP custody follow-up

Source review found that the final `finish_acknowledged_reset` check omitted ordinary HTTP streams and cancellation jobs retained after stream removal. Normal `finish_route_drain` already waits for HTTP cleanup before unbinding, so this is an independent reset-invariant check, not evidence of an observed leak through that normal path. `SocketLifecycle::is_drained` now checks all HTTP streams and the exact `http_cleanup_custody::Scope` queue as well as sockets/handshakes. Scope observation does not start a cleanup worker, cancel a request or wait for an acknowledgement; pending unattached reservations and failed/in-flight cancellation remain outstanding. Reset retains the original route until this complete network check succeeds.

Generated source controls: `reset_network_drain_counts_ordinary_http_streams_and_unattached_admissions` checks ordinary streams, pre-start admission and sibling isolation; `drop_retains_failed_cancellation_without_waiting_and_exact_scope_drains_after_ack` now checks nonblocking drain observations before/after the original broker acknowledgement. Added `reset_cleanup_keeps_all_retired_routes_until_last_sibling_releases_custody` to require all sibling routes to retain cleanup authority after one outstanding lease blocks reset, followed by atomic release only after the last lease is cancelled. No tests/builds ran; whole-process teardown and churn qualification remain open.

## September 17 parked observer notification custody

The agent-level MutationObserver and slot-change dispatcher previously checked retirement but not temporary document suspension. It now retains suspended notifications without invoking them, continues active siblings, and reports only runnable work to the host checkpoint loop. Slot scheduling resolves the wrapper's current native owner after adoption. Retained batch guards preserve suspended notifications and interrupted suffixes; successful whole-forest restoration requeues notifications only after parent authority, domain tokens, native microtask queues and suspension flags have been restored. Retirement discards the queued callbacks through the existing retired-state path.

Generated `parked_observer_and_slot_notifications_wait_without_blocking_active_siblings` covers active-sibling delivery, repeated parked-only checkpoints without rescheduling, restore delivery and discard suppression.
